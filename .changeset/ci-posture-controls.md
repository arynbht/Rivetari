New CI/CD posture controls check that an installed repo's GitHub Actions follow the fast-CI shape, each with a fix that edits the workflows in place and keeps their comments. `ci.required-aggregator`: one `ci` job needs other PR jobs (a job may be left out on purpose), runs with `if: always()` and reads their results to fail when one failed (the fix adds that job needing every PR job, or turns an existing `ci` job into it). `ci.concurrency-pr-only`: superseded PR runs are cancelled (`cancel-in-progress` on `github.event_name == 'pull_request'`) and default-branch runs are grouped by commit, so they're never cancelled or replaced. `ci.job-timeouts`: every job sets `timeout-minutes` (the fix sets 30). `ci.docs-skip-build`: docs-only PRs skip build and test (the fix adds a `changes` job with dorny/paths-filter and gates the other jobs on it, leaving the required `ci` job and the secret scan ungated, since GitHub counts a skipped required check as passed). `ci.pr-linux-only`: on a private repo, GitHub-hosted Windows and macOS runners stay off pull requests (self-hosted ones don't count) (the fix narrows a mixed OS matrix to its Linux runners on PRs, or keeps a Windows- or macOS-only job off PRs; a required `ci` job on Windows or macOS is left running and the fix says to move it to Linux by hand). `ci.secret-scan-on-pr` (harden): a PR workflow runs gitleaks or TruffleHog over the PR's commits (the fix adds a `secret-scan` job running TruffleHog, which needs no license on an organization's repo). `ci.actions-pinned-sha`'s fix now pins each tag-pinned `uses:` to the commit the tag points at, read from the GitHub API, keeping the tag as a comment. They run on the new `workflow` detector type and `workflow` fix type. Rivetari's CI workflow template now sets `timeout-minutes` and cancels only PR runs.
