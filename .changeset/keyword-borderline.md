The router decides a borderline sector whose whole score comes from description keywords, such as observability from the word "metrics", as not in. The route's ledger records `decided not in: <sector> (scored only on description keywords)`, and at review-at-pr such a sector no longer holds the route for a person, whether the task is routed now or resumed from its ledger. A borderline sector that also scores from a path, a title keyword, a skill's trigger or the repo's infrastructure as code still holds the route. Keyword-only sectors stay in the borderline list the approver is shown. The runtime's `Routing` gains `decidedOut`.
